# CUMCM 摘要专项指南

仅在起草、压缩或审计摘要时读取本文件。摘要应在 G5 结论与图表证据形成后起草，在正文、关键结果和适用范围稳定后定稿；不得用摘要提前冻结尚未验证的结论。

## 信息任务

摘要需要让读者快速知道每个子问题：

1. 做了什么：现实任务、关键假设和模型的数学结构；
2. 得到什么：有区分度的结论、决策或数值；
3. 为什么可信：与该题型相匹配的验证或反证。

不要求每个子问题各占一个独立段落，也不强制固定句序。可根据篇幅、问题依赖和所用模板合并表达，但不能因此省略某个子问题的结论或证据边界。

## 方法表达

- 描述数学结构和作用，例如“以容量和时间窗为约束的整数路径优化”，不要只列“遗传算法、TOPSIS、ARIMA”。
- 说明基线与改进分别解决什么问题；没有实际运行的候选不要包装成采用方法。
- 多阶段模型要交代接口：上一问的哪个输出进入下一问，以及误差如何影响后续结论。

## 结果与可信度

- 关键结果优先给出数值、单位、样本范围或成立条件；不能用单个数字概括时，可给区间、排序稳定区间、约束残差、可行率或机制判断。
- 可信度证据应按题型选择：预测给基线和样本外误差，优化给约束残差与求解状态，评价给权重扰动和排名稳定性，仿真给守恒/平衡与收敛，随机算法给重复分布。
- 摘要中的数字仍遵守现有严格追溯契约：先成为 result metric，再由 claim 的 `numeric_assertions` 绑定单位、展示值和容差。

以下措辞没有对应证据时禁止使用：

- “效果良好”；
- “精度较高”；
- “显著提升”；
- “全局最优”；
- “鲁棒性很强”。

应改为可核验表述，例如“相对同一时间切分下的朴素基线，测试集 MAE 从 8.4 降至 6.9”，并同时说明样本范围和比较条件。

## 三类反例

### 流程目录式

反例：“首先分析问题，然后建立模型，最后求解并检验模型。”

问题：只重复论文目录，没有模型结构、结果或可信度证据。改写时用任务—结构—结果—验证替代流程词。

### 无数字式

反例：“模型预测效果较好，优化方案明显节约成本。”

问题：无法判断比较对象、幅度、单位和适用范围。改写时加入已登记的结果、基线和条件；若当前证据不能支持数字，就降低结论强度并明确仍待验证。

### 过度承诺式

反例：“遗传算法获得全局最优解，证明方案具有很强鲁棒性。”

问题：启发式搜索结果不自动具备全局证书，单次敏感性图也不能证明强鲁棒性。改写为“在给定预算的多次搜索中得到当前最好可行解”，并报告可行性、上下界或扰动结果。

## 定稿检查

- [ ] 每个顶层子问题都有任务、结论和可信度依据；
- [ ] 方法写出数学结构及其作用，而非算法名堆叠；
- [ ] 关键数字、单位、样本范围和条件与 result/claim 一致；
- [ ] 基线、样本外误差、约束残差、稳定性或收敛证据按题型出现；
- [ ] “显著、最优、准确、稳健”等强措辞未越过证据；
- [ ] 没有正文未支持的新结论、临时手算数字或隐藏失败；
- [ ] 摘要与正文、结论、图表和最终 PDF 使用同一冻结版本；
- [ ] 篇幅、关键词和排版符合本项目人工确认的模板要求。

`lint_paper.py` 只检查其已实现的结构、引用、占位符、引擎污染、登记标记和可选 PDF 条件；它不判断摘要的信息密度、数学真实性、论证力度或写作质量。摘要必须由人结合正文和证据逐句复核。
