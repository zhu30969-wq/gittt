# CUMCM 能力量表与质量门禁

本量表用于内部评审、阶段门禁和复盘，不是官方 CUMCM 评分表，也不能据此推断获奖概率。

## 通用评分锚点

| 分数 | 含义 |
|---:|---|
| 0 | 缺失，或与题目明显无关 |
| 1 | 只出现术语、模板或未经支持的断言 |
| 2 | 有部分内容，但定义、实现或证据存在明显缺口 |
| 3 | 形成完整可用的基础方案，主要限制已说明 |
| 4 | 证据充分，经过适用验证，模型、代码和论文一致 |
| 5 | 有独立复核或强压力测试，可复现，边界和不确定性解释清楚 |

评分必须引用具体产物、运行、公式、图表或审计结果。不得根据文字流畅度推测数学正确性。

## 十五维量表

| 维度 | 权重 | 3 分要求 | 5 分特征 |
|---|---:|---|---|
| 问题理解与抽象 | 8 | 顶层问题、输入输出、依赖和成功判据完整 | 歧义有对照解释和证据，抽象保留关键机制 |
| 假设与简化 | 7 | 假设必要且在模型中被使用 | 关键假设经敏感性、反事实或外部证据检验 |
| 理论知识与模型选择 | 7 | 选择与问题结构相符并保留基线 | 候选经公平比较，拒绝理由和适用边界清楚 |
| 模型构建 | 12 | 变量、参数、方程、目标和约束闭合 | 数学结构严密，接口和误差传播明确 |
| 数学工具与计算 | 7 | 推导和数值方法能支持求解 | 有独立验算、界、收敛或特殊情形验证 |
| 编程与软件 | 7 | 代码可运行，模块与模型对应 | 自动化、测试、环境和日志支持独立复现 |
| 数据处理与统计 | 7 | 数据来源、字段、清洗和划分合理 | 泄漏、偏差、异常和测量不确定性均被评估 |
| 实验与仿真 | 5 | 实验设计能回答模型问题 | 预注册比较、消融或高区分度实验充分 |
| 模型验证与不确定性 | 10 | 完成题型适用的关键验证 | 多层验证、稳健性和失效范围清楚 |
| 结果解释与可视化 | 6 | 图表服务结论，单位和含义明确 | 关键现象、机制、反例和不确定性表达高效 |
| 写作与报告 | 8 | 结构完整，公式、图表和引用一致 | 摘要高信息密度，论证清楚且可快速核查 |
| 团队协作与项目管理 | 5 | 有明确负责人、交接和复核 | 交叉理解、版本控制和独立复核形成闭环 |
| 创新与批判性思维 | 5 | 有针对题目的改进或洞见 | 创新产生可验证增益，且主动识别自身弱点 |
| 时间管理与竞赛执行 | 3 | 关键冻结点和交付节奏合理 | 在限制下保住可靠基线、验证和成稿质量 |
| 可复现性与证据追溯 | 3 | 关键结果可回到运行和数据 | 干净重跑通过，结论、图表和运行逐项追溯 |

权重合计 100。加权分计算为：

~~~text
总分 = Σ（维度得分 ÷ 5 × 维度权重）
~~~

## 硬性质量失败

总分不能覆盖以下失败。存在任一项时不得标记 SUBMISSION_READY：

- 顶层问题或关键单位尚未确认；
- 关键结果无法由登记代码和数据重现；
- 优化解违反关键约束或整数性；
- 预测结论存在明确数据泄漏；
- 机理模型存在未解释的量纲、边初值或收敛错误；
- 论文出现编造、错配或无法追溯的关键数值；
- 模型规格、代码和论文对同一变量或公式含义不一致；
- 最终 PDF 无法正常生成或关键页面不可读；
- G0 至 G7 中应由人确认的门禁仍待批准。

这些是成果可信度失败，不是格式扣分。

## 阶段性使用

### G0 前

先检查输入清单、题面、附件、数据版本和散列是否互相对应。G0 不计算能力得分；输入尚未确认时，后续评分只能作为临时诊断。

### G1 前

重点评：

- 问题理解与抽象；
- 假设与简化的初步合理性；
- 数据处理中的字段、单位和来源；
- 团队是否形成共同题意。

问题理解低于 3 分时不得进入 MODELING。

### G2 前

重点评：

- 理论知识与模型选择；
- 模型构建；
- 数学工具；
- 实验计划；
- 创新是否来自任务需要而非方法堆叠。

模型构建低于 3 分，或没有可比较基线且无合理说明时，不得冻结模型。

### G3 前

重点评：

- 编程与软件；
- 数据处理与统计；
- 实验与仿真；
- 基线、公平比较和预先登记的接受规则；
- 时间与计算预算。

实验设计低于 3 分，或比较口径会系统性偏向某个候选时，不得冻结 experiment。

### G4 前

重点评：

- 编程与软件；
- 数据处理与统计；
- 实验与仿真；
- 模型验证与不确定性；
- 可复现性与证据追溯。

验证维度低于 3 分，或存在硬性质量失败时，不得冻结结果。

### G5 前

重点评：

- 模型验证与不确定性；
- 结果解释与可视化；
- 结论力度与证据是否匹配；
- 可复现性与证据追溯。

关键 claim 缺少 result 或证明依据，图表来源不明，或限制被隐藏时，不得冻结结论与图表。

### G6 前

重点评：

- 写作与报告；
- 图表和解释；
- 全链路追溯。

G6 使用最终 PDF 和冻结结果评分，不能只评源文件或初稿。

### G7 前

重点评：

- 团队交叉复核；
- 时间与最终交付；
- 可复现性与证据追溯；
- 发布包中的论文、代码、结果和 manifest 是否为同一版本。

任何旧审批、过期产物或缺失交付物都不能由总分抵消。

## 内部结果分级

在无硬性失败且核心维度均不低于 3 分时，可用总分安排优先级：

| 总分 | 内部解释 |
|---:|---|
| 90–100 | 证据链强，可集中做最后压缩和独立复核 |
| 80–89 | 整体可靠，仍需修复少数明确弱项 |
| 70–79 | 基础方案可用，但至少一个高权重环节需要实质改进 |
| 0–69 | 不宜继续润色，应回到最早的薄弱阶段 |

该分级只用于内部资源分配。不得写成获奖等级预测。

## 评审输出格式

每次评审至少输出：

| 字段 | 内容 |
|---|---|
| 维度 | 被评价能力 |
| 分数 | 0 至 5 |
| 权重 | 本量表权重 |
| 证据 | 文件、方程、运行、图表或页码 |
| 缺口 | 为什么没有更高分 |
| 风险 | 对后续结论或交付的影响 |
| 动作 | 最小有效修复 |
| 回退状态 | FRAMING、MODELING、COMPUTING、VALIDATING 或 WRITING |

评审结尾增加置信度：

- **非常确定**：证据完整，可重跑或有独立复核；
- **需验证**：证据部分可用，但缺少关键运行、外部核对或人工确认；
- **推测**：主要依赖间接材料或未验证假设。

不确定时降低置信度，不通过虚高分数掩盖证据缺口。
