# 案例层使用规范

案例层用于学习历年 CUMCM 题目的问题拆解、模型接口、验证方式、图表论证和论文表达。它不是答案库，也不能替代当前赛题的数据和机制。

训练模式和正式赛模式都可以按任务需要使用案例；区别仅在正式赛应控制检索时间，避免案例阅读挤占建模、验证和交付。

## 默认使用顺序

除非用户明确要求案例检索或论文对比，否则按以下顺序：

1. 独立写出当前问题的结构签名。
2. 建立简单基线和初步候选。
3. 记录当前最不确定的判断。
4. 按结构而非题目关键词检索案例。
5. 提取可迁移模式、失败教训和验证方法。
6. 明确案例与当前题目的差异。
7. 用当前数据和验证重新决定是否采用。

先记录独立判断可以降低“看到优秀论文后反向合理化”的锚定风险。

## 结构化检索

优先按以下字段匹配：

- 任务：预测、识别、评价、优化、控制、仿真或解释；
- 对象：个体、网络、空间、时间、资源分配或动态系统；
- 数据：横截面、时序、面板、实验、文本、图像或无附件；
- 决策：连续、整数、路径、多目标、情景或在线决策；
- 机制：守恒、扩散、排队、竞争、传播、几何或行为；
- 验证：样本外、回代约束、残差、收敛、扰动、消融或外部事实；
- 可复现性：是否有数据、代码、环境和明确参数。

“题目都涉及交通”通常不如“带容量和时间窗的离散路径决策”有迁移价值。

## 案例卡字段

每个被实际采用的案例至少记录：

| 字段 | 说明 |
|---|---|
| 案例 ID | 稳定标识 |
| 年份与题号 | 便于追溯 |
| 来源 | URL、文件或明确出处 |
| 问题结构 | 不使用笼统主题词 |
| 数据结构 | 样本、时间、空间和测量特征 |
| 模型路线 | 只作事实描述 |
| 验证方式 | 是否真正检验了结论 |
| 可迁移经验 | 可用于当前题目的结构性做法 |
| 关键差异 | 为什么不能直接照搬 |
| 已知缺陷 | 论文未回答或无法复现之处 |
| 复现等级 | 完整复现、部分复现、论文可读、仅元数据 |
| 当前用途 | 候选生成、验证设计、写作参考或反例 |

只有论文 PDF 而没有代码和数据时，应标为“论文可读”，不得描述成已复现案例。

## 证据优先级

发生冲突时依次信任：

1. 当前题面、附件和经确认的问题定义；
2. 当前项目可重跑的实验与验证；
3. 定义相同且可复现的外部案例；
4. 有明确方法和结果但不可复现的论文；
5. 教程、心得和未注明出处的算法清单。

“获奖”只能说明案例值得研究，不能证明其每个假设、公式和数值都正确。

## 可迁移与不可迁移

通常可迁移：

- 子问题间的接口设计；
- 基线和对照实验；
- 数据泄漏、量纲、约束方向等防错方法；
- 灵敏度、收敛和稳健性检查；
- 摘要如何呈现方法、结果和限制；
- 图表如何支撑论证。

通常不可直接迁移：

- 未重新核对的参数值；
- 题目专属数据清洗阈值；
- 结论数值和图表数据；
- 因题面定义不同而成立的目标或约束；
- 案例论文中的措辞、推导和段落；
- 未经当前数据验证的“最佳模型”判断。

## 防止案例驱动套模

采用案例中的方法前必须回答：

1. 当前问题与案例共享的数学结构是什么；
2. 哪些关键定义或数据生成过程不同；
3. 案例模型的必要假设在当前题目中是否成立；
4. 当前题目的基线是什么；
5. 哪个验证能区分“真正适用”和“仅表面相似”；
6. 如果案例方法失败，回退方案是什么。

不能回答时，只把案例作为启发或反例，不进入模型规格。

## 多案例比较

比较案例时使用同一张提取表，避免只摘录支持既有观点的部分。重点比较：

- 不同论文如何解释题意；
- 模型复杂度和数据量是否匹配；
- 验证是否能发现失败；
- 关键结论是否可追溯；
- 哪些亮点来自表达，哪些来自真正的新证据；
- 同一路线在什么条件下给出不同结果。

不需要为了数量收集大量案例。当新增案例不再改变候选、验证方案或风险判断时停止检索。

## 在论文中的使用

案例可用于背景、方法来源或路线比较，但当前论文的关键结果必须来自当前项目运行。引用案例时：

- 只陈述实际阅读到的内容；
- 不把案例结论改写成当前结论；
- 保留来源；
- 对不可复现内容使用有限措辞；
- 不用案例数量替代当前验证。
